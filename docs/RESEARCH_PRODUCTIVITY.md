# Research productivity features

- **Research brief:** goal, audience and geography are optional. Existing publication date filters provide the date range. The original question stays intact; requested scope appears in planning and report methodology.
- **Version comparison:** open a completed report's support panels, choose another saved report, and inspect exact-text claim additions, changed evidence statuses, omissions and gaps. Paraphrases may appear as different records; these are not automatically discoveries or refutations.
- **Collections:** open Research library in the sidebar. Create/rename a collection, select up to ten reports, ten chats and five PDFs, then save or ask the collection. Cloud collection answers load only the owner's selected records and use the existing bounded Gemini retrieval/streaming path. Conversation statements are labeled unverified. Browser-only mode supports smaller locally saved collections (three million characters maximum); cloud context is capped at sixteen million UTF-8 bytes. Removing an attachment or deleting its underlying record excludes it from subsequent cloud questions. Persisted collection chats retain the collection reference.
- **Feedback:** choose the whole report or a section, select Helpful/Missing information/Citation issue, and save a note. Feedback stays in the owner's workspace. It is not automatically emailed to the creator.
- **Checkpoints:** opt in before research starts. Collection reserves part of its iteration/source/time budget. The review panel lists collected sources and up to three selectable gaps for remaining budget; exhausted budgets disable further investigation. Continue proceeds normally. The review expires after fifteen minutes, cancellation releases the wait, and old tokens are rejected. Pause time is excluded from research execution time. Checkpoints are process-local; an interrupted backend run cannot resume its checkpoint after a restart.
- **Sharing:** a completed report can explicitly publish an immutable read-only snapshot for thirty days. A new link replaces the previous one. Revoke works across refreshes. Tokens are random and only their hashes are stored. Public output excludes workspace identity, chat history, PDF files, raw source bodies and audit state. Deleting the underlying report makes its share unavailable. Shared report routing is configured for Vercel.
- **Alerts:** Google-signed-in users can enable daily or weekly Quick-mode updates, with at most three active alerts. Each update uses the app's current provider/search quotas and server concurrency limits. Database dates and atomic claims avoid multiple workers taking the same due check. The library shows new source URLs/changed claim records, without claiming that paraphrases prove new discoveries. Pause/resume and manual refresh are available. No email or paid external scheduler is introduced.

## Deployment and reliability

Migration `supabase/migrations/20261010192350_research_productivity.sql` was applied to the existing project with explicit user approval. Private share/alert tables have RLS, no client grants, and service-role-only backend access. Alert RPCs use security invoker and are executable only by the backend role. The existing ownership policies protect collection/feedback records.

Deploy the frontend and backend together. The FastAPI lifespan starts one alert worker per backend process; due checks are polled every minute and claimed atomically. **An awake backend is required:** a sleeping/free backend cannot guarantee scheduled timing. Missed dates are handled when it wakes. A crash during a run may leave that saved run interrupted; its next scheduled date remains durable. A production always-on worker or an explicitly approved external scheduler is needed for strict unattended timing. No deployment plan or paid service was changed in this pass.

Existing clients can omit the optional `brief` and `review_checkpoint` request fields. Existing SSE envelopes are unchanged; opted-in reviews add `research_checkpoint` and `checkpoint_resumed` event types.

## Verification

Run `python -m pytest -q` from the repository root and `node --test tests/*.test.mjs` plus `npm run build` from `frontend/`. New tests cover ownership, privacy, token handling, checkpoint replay/decisions, brief bounds, iteration accounting, alert guest/limit behavior, offline collection persistence and version comparison. Tests use synthetic data and no real model calls. Live model quality, exact scheduled delivery on the deployed Render service, and elapsed thirty-day link expiry require deployment/end-to-end verification.
